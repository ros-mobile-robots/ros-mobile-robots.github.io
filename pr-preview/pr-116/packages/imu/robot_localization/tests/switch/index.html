    Test: The ekf Switch of the Launch Files

    This page belongs to Localization: Wheel Odometry and IMU (EKF). It walks through test_ekf_switch.py, the test of the ekf argument in the launch files.

    The ekf argument has to do several things at once in several launch files, as Which launch file starts what shows. With ekf:=true, a launch file starts the EKF and the IMU sample validator, turns off the drive controller's transform odom → base_footprint and makes the planner read the EKF's odometry. Without it, none of this may happen. The test proves that the launch files are written this way, for both positions of the switch and for its default. The test reads the launch files and starts nothing. So it doesn't prove that the nodes run or that they work together. The stepped-clock test and the test in Gazebo start them.

    Reading a launch file without starting it

    roslaunch has a loader that reads a launch file and everything that the file includes, and returns what roslaunch would start: the nodes, the parameters and the remappings. The test calls this loader and looks at the result. No ROS master and no node run.

    The figure shows this flow from top to bottom, for one launch file and its arguments. The test's function load() gives them to roslaunch's loader, load_config_default(). load() returns the loader's result as a LaunchConfiguration with three fields, and the test's assertions look at these fields. The dashed box is what roslaunch would do after loading, which the test leaves out.

    class LaunchConfiguration(NamedTuple):
    """What roslaunch would start: the nodes by their full name, and the parameters."""

    nodes: Dict[str, Node]
    parameters: Dict[str, Any]
    description: str  # the launch file and its arguments, for failure messages


def load(package: str, launch_file: str, **args: str) -> LaunchConfiguration:
    """Return what roslaunch would start for the package's launch file with the arguments."""
    path = os.path.join(PACKAGES.get_path(package), 'launch', launch_file)
    argv = ['{}:={}'.format(name, value) for name, value in args.items()]
    config = load_config_default([(path, argv)], None, verbose=False)
    nodes = {}
    for node in config.nodes:
        name = '/' + '/'.join(part for part in (node.namespace.strip('/'), node.name) if part)
        nodes[name] = node
    parameters = {name: parameter.value for name, parameter in config.params.items()}
    description = ' '.join([package, launch_file] + argv)
    return LaunchConfiguration(nodes, parameters, description)
    • load(): takes a package, the name of a launch file in the package's launch folder and the launch arguments. load('diffbot_gazebo', 'diffbot.launch', ekf='true') stands for the command roslaunch diffbot_gazebo diffbot.launch ekf:=true.
    • load_config_default(): is roslaunch's loader. It resolves the includes, the arguments and the conditions such as if="$(arg ekf)", as roslaunch does before it starts anything.
    • nodes: a dictionary from each node's full name, for example /diffbot/ekf_localization, to roslaunch's description of the node. The loader keeps a node's namespace and its name apart, so load() joins them.
    • parameters: a dictionary from each parameter's full name to its value.
    • description: the launch file with its arguments, as text. Every failure message starts with it.

    def assert_ekf_on(self, package: str, launch_file: str) -> None:
    """Assert everything that ekf:=true has to do in the package's launch file."""
    configuration = load(package, launch_file, ekf='true')
    self.assert_ekf_nodes_start(configuration)
    self.assert_controller_odom_tf(configuration, enabled=False)
    self.assert_ekf_reads_the_controller_and_the_validator(configuration)
    self.assert_state_publisher_starts(configuration)

def assert_ekf_off(self, package: str, launch_file: str) -> None:
    """Assert that the launch file runs without the EKF, with ekf:=false and by default."""
    for switch in SWITCHED_OFF:
        configuration = load(package, launch_file, **switch)
        self.assert_no_ekf_nodes_start(configuration)
        self.assert_controller_odom_tf(configuration, enabled=True)

def assert_ekf_switch(self, package: str, launch_file: str) -> None:
    """Assert both positions of the switch in the package's launch file."""
    self.assert_ekf_off(package, launch_file)
    self.assert_ekf_on(package, launch_file)

    Off, assert_ekf_off(), once with ekf:=false and once without the argument:

    1. assert_no_ekf_nodes_start(): neither EKF_NODE, which is /diffbot/ekf_localization, nor VALIDATOR_NODE, which is /diffbot/imu_validator, is among the nodes.
    2. assert_controller_odom_tf(configuration, enabled=True): the parameter ODOM_TF_PARAMETER, which is /diffbot/mobile_base_controller/enable_odom_tf, is set, and its value is True. So the drive controller publishes the transform.

    On, assert_ekf_on(), with ekf:=true:

    1. assert_ekf_nodes_start(): both nodes are among the nodes, EKF_NODE from the package robot_localization with the executable ekf_localization_node, and VALIDATOR_NODE from diffbot_control with imu_validator.py.
    2. assert_controller_odom_tf(configuration, enabled=False): enable_odom_tf is set, and its value is False. So only the EKF publishes the transform.
    3. assert_ekf_reads_the_controller_and_the_validator(): the five parameters in EKF_PARAMETERS have their values. The EKF works in the frame odom for the frame base_footprint, reads the topics mobile_base_controller/odom and imu/data_validated, and the validator expects the frame imu_link.
    4. assert_state_publisher_starts(): STATE_PUBLISHER_NODE, which is /diffbot/robot_state_publisher, is among the nodes. The EKF needs the transform between imu_link and base_footprint, which TF has from robot_state_publisher.

    def assert_node(self, configuration: LaunchConfiguration, name: str, package: str,
                node_type: str) -> None:
    """Assert that the launch file starts the node name from package's node_type."""
    self.assertIn(name, sorted(configuration.nodes),
                  "{} doesn't start {}".format(configuration.description, name))
    node = configuration.nodes[name]
    self.assertEqual((package, node_type), (node.package, node.type),
                     '{}: the executable of {}'.format(configuration.description, name))

def assert_ekf_nodes_start(self, configuration: LaunchConfiguration) -> None:
    """Assert that the launch file starts the EKF and the IMU sample validator."""
    self.assert_node(configuration, EKF_NODE, 'robot_localization', 'ekf_localization_node')
    self.assert_node(configuration, VALIDATOR_NODE, 'diffbot_control', 'imu_validator.py')

def assert_no_ekf_nodes_start(self, configuration: LaunchConfiguration) -> None:
    """Assert that the launch file starts neither the EKF nor the IMU sample validator."""
    for name in (EKF_NODE, VALIDATOR_NODE):
        self.assertNotIn(name, sorted(configuration.nodes),
                         '{} starts {}'.format(configuration.description, name))

def assert_controller_odom_tf(self, configuration: LaunchConfiguration,
                              enabled: bool) -> None:
    """Assert that the launch file sets the controller's enable_odom_tf to enabled.

    Set, not left out: roslaunch writes each parameter at each start, so a false value from
    an earlier run with the EKF on the same ROS master doesn't remain.
    """
    self.assertIs(enabled, configuration.parameters.get(ODOM_TF_PARAMETER),
                  "{}: the controller's enable_odom_tf".format(configuration.description))

def assert_ekf_reads_the_controller_and_the_validator(
        self, configuration: LaunchConfiguration) -> None:
    """Assert the EKF's frames and inputs and the validator's frame (EKF_PARAMETERS)."""
    for name, value in EKF_PARAMETERS.items():
        self.assertEqual(value, configuration.parameters.get(name),
                         '{}: {}'.format(configuration.description, name))

def assert_state_publisher_starts(self, configuration: LaunchConfiguration) -> None:
    """Assert that the launch file starts robot_state_publisher.

    The EKF looks up imu_link → base_footprint, which TF has from robot_state_publisher.
    """
    self.assertIn(STATE_PUBLISHER_NODE, sorted(configuration.nodes),
                  '{} starts the EKF without robot_state_publisher'.format(
                      configuration.description))

    The launch file has to write enable_odom_tf in both positions, because a parameter stays on the ROS parameter server as long as the ROS master runs. A false from a launch with the EKF would otherwise remain for a later launch without it.

    The planner's odometry topic

    A planner reads the robot's velocity from an odometry topic. With the EKF on, the planner has to read the EKF's estimate, so that its velocity and the transform come from the same estimate.     def assert_planner_odometry(self, configuration: LaunchConfiguration, node_name: str,
                            topic: str) -> None:
    """Assert that the planner node_name reads its odometry from topic."""
    self.assertIn(node_name, sorted(configuration.nodes),
                  "{} doesn't start {}".format(configuration.description, node_name))
    self.assertEqual(topic, remapping(configuration.nodes[node_name], 'odom'),
                     "{}: {}'s odom".format(configuration.description, node_name))

def assert_planner_follows_the_switch(self, package: str, launch_file: str,
                                      node_name: str) -> None:
    """Assert that the planner reads the EKF's odometry with ekf:=true only."""
    self.assert_planner_odometry(load(package, launch_file), node_name, WHEEL_ODOMETRY_TOPIC)
    self.assert_planner_odometry(load(package, launch_file, ekf='true'), node_name,
                                 FILTERED_TOPIC)
    • assert_planner_odometry(): the planner's node is among the nodes, and its name odom is remapped to topic.
    • assert_planner_follows_the_switch(): without the ekf argument, the planner reads WHEEL_ODOMETRY_TOPIC, the topic /diffbot/mobile_base_controller/odom. With ekf:=true, it reads FILTERED_TOPIC, the topic /diffbot/odometry/filtered.

def test_planner_reads_an_explicit_odom_topic_also_with_ekf_true(self) -> None:
    configuration = load('diffbot_navigation', 'move_base.launch', ekf='true',
                         odom_topic='/other/odom')
    self.assert_planner_odometry(configuration, MOVE_BASE_NODE, '/other/odom')
    • Three files with move_base: move_base.launch, diffbot_navigation.launch and diffbot_hw.launch of diffbot_navigation start the planner /move_base, the test's MOVE_BASE_NODE.
    • One file with Move Base Flex: amcl_demo.launch of diffbot_mbf starts the planner /move_base_flex, the test's MOVE_BASE_FLEX_NODE.
    • An explicit topic wins: move_base.launch has an odom_topic argument. Its default is the EKF's topic with ekf:=true and the controller's topic without it. With odom_topic:=/other/odom and ekf:=true, the planner reads /other/odom.

    These launch files start no EKF, so the test checks nothing else in them.

    What the test doesn't show

    • Running nodes: the loader reads the launch files. Nothing starts, so the test can't see whether a node runs, publishes or finds its transforms.
    • robot_state_publisher in every file: the test asserts robot_state_publisher for the two bringup files and for diffbot_gazebo's diffbot.launch. It doesn't assert the node for minimal.launch, which doesn't start it.
    • ekf:=false for the planners: for the planners' launch files, the test loads the default and ekf:=true.
    • Other ways to start the robot: the robot container starts bringup.launch without ekf. The test doesn't read the container's settings.
