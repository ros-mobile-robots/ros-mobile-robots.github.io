    Tests: The IMU Sample Validator

    What the unit tests of the IMU sample validator check, and how they do it. This page belongs to the tests of the Localization.

    test_imu_validator.py tests the IMU sample validator one decision at a time. Its 27 unit tests call the validator's Python class and functions directly. No ROS master runs, no node starts and no message travels over a topic. The tests prove what the validator decides for a given sample at a given ROS time \(t\), and what its diagnostics report. They don't prove that the node forwards the samples on its topic or that the EKF handles them. The stepped-clock test checks the node together with the EKF.

    The file has four test classes, one for each part of imu_validator.py that works without ROS communication:

    Test class Tests What it calls What it checks
    TestImuValidator 11 ImuValidator.validate_and_record() Which samples the validator forwards, and the reason for each sample that it drops
    TestSecondsSinceLastValidSample 7 ImuValidator.seconds_since_last_valid_sample() The time since the last valid sample, which the diagnostics report, also when the clock goes back
    TestHealth 5 health() The level of the diagnostics status: OK, warning or error
    TestSampleCounts 4 SampleCounts The counts of forwarded and dropped samples in a diagnostics report

    What the tests don't show lists what a pass doesn't prove.

    The clock and the sample of the tests

    The validator never reads the ROS clock itself. validate_and_record() and seconds_since_last_valid_sample() get the ROS time \(t\) as their argument now. So a test can choose any ROS time and any stamp \(t_s\), and needs no clock and no waiting.

    def sample(stamp: rospy.Time = NOW, frame_id: str = FRAME, yaw_rate: float = YAW_RATE) -> Imu:
    """Return a valid sample, like the firmware's."""
    message = Imu()
    message.header.stamp = stamp
    message.header.frame_id = frame_id
    message.orientation_covariance[0] = ORIENTATION_UNAVAILABLE
    message.angular_velocity.z = yaw_rate
    message.linear_acceleration.z = GRAVITY
    for index in VARIANCE_INDICES:
        message.angular_velocity_covariance[index] = ANGULAR_VELOCITY_VARIANCE
        message.linear_acceleration_covariance[index] = LINEAR_ACCELERATION_VARIANCE
    return message


def seconds(value: float) -> rospy.Duration:
    """Return a duration of value seconds."""
    return rospy.Duration.from_sec(value)
    • sample(): returns a sensor_msgs/Imu message that passes all five checks at the ROS time NOW. Its stamp \(t_s\) is NOW, its frame is imu_link, its yaw rate \(\omega_z\) is YAW_RATE, 0.5 rad/s, and its upward acceleration \(f_z\) is GRAVITY. The variances \(\sigma^2\) on the diagonals of the two covariances have the size of the firmware's. orientation_covariance[0] is −1, which marks the orientation as unavailable, as in the firmware's message.
    • The arguments: a test passes stamp, frame_id or yaw_rate to change one property of the sample. For the other invalid samples, a test changes one field of the message that sample() returned. So each case aims at one check. A sample can fail a later check too, as the too-old sample of the time limits does.
    • seconds(): turns a number of seconds into a rospy.Duration, which a test adds to NOW or subtracts from it.

    def test_validator_drops_a_sample_with_a_nan_or_infinite_value(self) -> None:

    def test_validator_drops_a_sample_with_an_invalid_angular_velocity_covariance(self) -> None:
    unavailable = sample()
    unavailable.angular_velocity_covariance = list(ANGULAR_VELOCITY_UNAVAILABLE)

    • nan_off_the_diagonal: the element with the index OFF_DIAGONAL_INDEX, 1, is NaN. This element is not a variance, so the test shows that the check looks at all nine values.

    def test_validator_forwards_a_sample_max_age_old_and_drops_an_older_one(self) -> None:

def test_validator_forwards_a_sample_max_future_ahead_and_drops_a_later_one(self) -> None:
    self.assertEqual(
        imu_validator.DropReason.FROM_THE_FUTURE,
        self.validator.validate_and_record(sample(NOW + seconds(JUST_TOO_FAR_AHEAD)), NOW))
    self.assertIsNone(
        self.validator.validate_and_record(sample(NOW + seconds(MAX_FUTURE)), NOW))
    • Sample B: its stamp is exactly MAX_AGE, 0.1 s, older than NOW. The validator forwards it, so the limit itself is still valid.
    • Sample A: its stamp is JUST_TOO_OLD, 0.100001 s, older than NOW. The validator drops it with DropReason.TOO_OLD.
    • Sample D: its stamp is JUST_TOO_FAR_AHEAD, 0.020001 s, ahead of NOW. The validator drops it with DropReason.FROM_THE_FUTURE.
    • Sample C: its stamp is exactly MAX_FUTURE, 0.02 s, ahead of NOW. The validator forwards it.

    In the first test, sample A is also older than the valid sample B before it. The validator reports DropReason.TOO_OLD and not DropReason.NOT_NEWER, because the checks run in their order and check 4 comes before check 5. The second test sends the dropped sample D first. For a dropped sample, the validator records only the ROS time of the call, so D doesn't change what the validator decides for C.

def test_validator_forwards_a_new_sample_after_dropping_a_future_one(self) -> None:
    # The order check compares with the last valid sample, not with a dropped one
    self.assertIsNone(self.validator.validate_and_record(sample(NOW), NOW))
    self.assertEqual(imu_validator.DropReason.FROM_THE_FUTURE,
                     self.validator.validate_and_record(sample(NOW + seconds(5)), NOW))
    self.assertIsNone(self.validator.validate_and_record(sample(NOW + seconds(MAX_FUTURE)),
                                                         NOW + seconds(MAX_FUTURE)))

    test_validator_drops_a_sample_not_later_than_the_last_valid_one sends four samples to one validator:

    1. A valid sample stamped NOW. The validator records NOW as \(t_\text{last}\).
    2. Sample F, stamped NOW again. The validator drops it with DropReason.NOT_NEWER, because a sample is valid only once.
    3. Sample E, stamped 0.01 s before NOW. The validator drops it with the same reason.
    4. Sample G, stamped 1 ns after NOW, the smallest step of a ROS stamp, at a ROS time 1 ms later. The validator forwards it.

    test_validator_forwards_a_new_sample_after_dropping_a_future_one shows what \(t_\text{last}\) is not. After a valid sample stamped NOW, the test sends sample H, stamped 5 s ahead. Check 4 drops H with DropReason.FROM_THE_FUTURE. Then the test sends sample I, stamped 0.02 s after NOW. The validator forwards I. If the validator had kept the stamp of the dropped sample H as \(t_\text{last}\), every sample of the next 5 s would count as not newer.

    def assert_silence(self, expected: float, now: rospy.Time) -> None:
    """Assert that seconds_since_last_valid_sample(now) is about expected."""
    silence = self.validator.seconds_since_last_valid_sample(now)
    if silence is None:
        self.fail('seconds_since_last_valid_sample() is None, expected {}'.format(expected))
    self.assertAlmostEqual(expected, silence)

def test_silence_is_none_before_the_first_valid_sample(self) -> None:
    self.assertIsNone(self.validator.seconds_since_last_valid_sample(NOW))

def test_silence_is_the_time_since_the_last_valid_sample(self) -> None:
    self.assertIsNone(self.validator.validate_and_record(sample(), NOW))
    self.assert_silence(1.5, NOW + seconds(1.5))

def test_silence_keeps_growing_while_samples_are_dropped(self) -> None:
    self.assertIsNone(self.validator.validate_and_record(sample(), NOW))
    later = NOW + seconds(3)
    self.assertEqual(imu_validator.DropReason.TOO_OLD,

    What the tests don't show

    • The node: the class ImuValidatorNode reads the parameters, subscribes to the topic imu/data_raw, publishes on the topic imu/data_validated and on the topic /diagnostics, and takes a lock around each sample. These tests don't call it. The stepped-clock test runs the node with the EKF and checks its counts on the topic /diagnostics.
    • The real clock and the real IMU: every time in these tests is a number that the test chose. Whether max_age and max_future fit the delays of the robot's USB link is a measurement on the robot, as Limits says.
    • The fields that the validator doesn't check: the overview lists them. No test sends a sample with an implausible but finite value, because the validator forwards such a sample by design.
