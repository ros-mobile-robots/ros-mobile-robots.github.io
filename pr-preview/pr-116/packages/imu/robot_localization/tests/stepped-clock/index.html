    Test: The EKF on a Stepped Clock

    What the stepped-clock test checks on the EKF and the IMU sample validator, and how the test does it. This page belongs to the tests of the Localization.

    test_ekf_synthetic.py runs the two nodes of ekf.launch, the IMU sample validator and robot_localization's EKF, with the parameters that the robot and the simulation use. The test computes their inputs itself: wheel odometry and IMU samples that report a constant yaw rate \(\omega_z\). The test also owns the clock. It publishes the topic /clock and moves the ROS time \(t\) on in steps of 20 ms. So the test decides which messages are published, with which stamps and at which ROS time, without Gazebo and without a robot.

    A pass proves four things about the filter's estimate of the yaw rate \(\omega_z\). The estimate follows the IMU while valid samples arrive. The estimate goes to the wheels' yaw rate when no valid sample arrives. Samples that the validator has to drop don't reach the estimate. And the estimate follows the IMU again after the clock went back. A pass also proves that the validator's counts on the topic /diagnostics match the samples that the test sent. What the test doesn't show lists what a pass doesn't prove.

    The inputs

    The test publishes on the two topics that the nodes read on the robot. The wheel odometry goes to the EKF on the topic /diffbot/mobile_base_controller/odom. The test subscribes to the validator's output, the topic /diffbot/imu/data_validated, to the filter's output, the topic /diffbot/odometry/filtered, and to the topic /diagnostics.

    def wheel_odometry(stamp: rospy.Time, yaw_rate: float) -> Odometry:
    """Return the drive controller's odometry at stamp, for a robot turning at yaw_rate."""
    message = Odometry()
    message.header.stamp = stamp
    message.header.frame_id = 'odom'
    message.child_frame_id = 'base_footprint'
    message.pose.pose.orientation.w = 1.0
    message.twist.twist.linear.x = SPEED
    message.twist.twist.angular.z = yaw_rate
    for axis, variance in enumerate(WHEEL_VARIANCES):
        message.pose.covariance[DIAGONAL_STRIDE * axis] = variance
        message.twist.covariance[DIAGONAL_STRIDE * axis] = variance
    return message


def imu_sample(stamp: rospy.Time, yaw_rate: float) -> Imu:
    """Return a sample as the firmware publishes it, in DiffBot's imu_link.

    DiffBot's imu_link is aligned with base_footprint.
    """
    message = Imu()
    message.header.stamp = stamp
    message.header.frame_id = 'imu_link'
    message.orientation_covariance[0] = ORIENTATION_UNAVAILABLE
    message.angular_velocity.z = yaw_rate
    message.linear_acceleration.z = GRAVITY
    for index in VARIANCE_INDICES:
        message.angular_velocity_covariance[index] = IMU_ANGULAR_VELOCITY_VARIANCE
        message.linear_acceleration_covariance[index] = IMU_LINEAR_ACCELERATION_VARIANCE
    return message
    • wheel_odometry(): a nav_msgs/Odometry message as the drive controller publishes it, in the frame odom with the child frame base_footprint. The forward speed \(v_x\) is SPEED, 0.1 m/s. The yaw rate \(\omega_z\) is the function's argument. The variances \(\sigma^2\) on the diagonals of both covariances are WHEEL_VARIANCES, with 0.03 (rad/s)² for the yaw rate. These are the numbers of diffbot_control.yaml, which the test writes out and doesn't read from the file.
    • imu_sample(): a sensor_msgs/Imu message as the firmware publishes it, in the frame imu_link. The orientation is marked unavailable, the yaw rate \(\omega_z\) is the function's argument, and the upward acceleration \(f_z\) is GRAVITY. The variance of the angular velocity is IMU_ANGULAR_VELOCITY_VARIANCE, 4 · 10⁻⁴ (rad/s)², the firmware's number, written out in the test too.
    • No noise: both messages report the same values in every step. So what the test sees in the estimate comes from the filter and the validator, not from chance.

def on_validated(self, message: Imu) -> None:
    """Note the stamp of a sample that the validator forwarded."""
    self.forwarded_stamp_keys.append(stamp_key(message.header.stamp))

def all_connected(self) -> bool:
    """Return whether the EKF and the validator subscribe and publish to the test."""
    return (self.wheel_odometry_publisher.get_num_connections() > 0
            and self.raw_imu_publisher.get_num_connections() > 0
            and self.validated_imu_subscriber.get_num_connections() > 0
            and self.filtered_odometry_subscriber.get_num_connections() > 0)
    1. setUp() sets the test's own ROS time self.now to START, 100 s, and creates the three logs and the two counters that the phases fill. self.forwarded_stamp_keys holds the stamps of the samples that the validator forwarded, self.ekf_outputs the filter's outputs, and self.diagnostics the messages of the topic /diagnostics. self.expected_forward_count and self.expected_drops count what the validator has to do with each sample that the test sends.
    2. setUp() creates the three publishers and the three subscribers. self.clock_publisher is latched, so a node that connects later still gets the last clock message. Each subscriber's callback appends what arrives to one of the three logs. For the validator's output, the callback is on_validated(), which appends the sample's stamp.
    3. setUp() publishes the clock for the first time, at START.
    4. setUp() waits until the validator and the EKF are connected to the test's topics, with all_connected(), and until TF has the transform from imu_link to base_footprint. Then it sleeps TF_DELIVERY, 1 s of wall time, so that the EKF's own TF listener has the transform too.

    class ArrivalLog(Generic[Item]):
    """What arrived on a topic, in the order of arrival.

    rospy calls a subscriber's callback in a thread of its own, which appends to the log, while
    the test's thread reads it. A lock guards every access, so that the test's thread never
    reads the log while the callback changes it.
    """

    def __init__(self) -> None:
        self._lock = threading.Lock()
        self._items: List[Item] = []

    def append(self, item: Item) -> None:
        """Add an item at the end."""
        with self._lock:
            self._items.append(item)

    def count(self) -> int:
        """Return the number of items so far."""
        with self._lock:
            return len(self._items)

    def since(self, count: int) -> List[Item]:
        """Return a copy of the items after the first count."""
        with self._lock:
            return self._items[count:]

    def contains_all(self, items: Sequence[Item]) -> bool:
        """Return whether each of the items has arrived."""
        with self._lock:
            return all(item in self._items for item in items)
    • append(): adds an item at the end. The subscribers of the filter's output and of the topic /diagnostics have it as their callback, and on_validated() calls it.
    • count(): returns the number of items so far. The test takes this number before a step.
    • since(): returns a copy of the items after the first count items. With the number from before a step, the test gets what arrived since the step started.
    • contains_all(): returns whether each of the given items has arrived.

    def wait_for(condition: Callable[[], bool], failure: str) -> None:
    """Wait on the wall clock until condition() is true, at most WAIT s, else fail with failure."""
    deadline = time.monotonic() + WAIT
    while not condition():
        if time.monotonic() > deadline:
            raise AssertionError(failure)
        time.sleep(POLL_INTERVAL)

    def advance(self, wheel_rate: float, imu_inputs: Sequence[ImuInput]) -> StepStart:
    """Do 1 to 4 of a step, as step() lists them, and return where the step started."""
    start = StepStart(self.now, self.ekf_outputs.count())
    valid_stamp_keys = self.publish_inputs(start.stamp, wheel_rate, imu_inputs)
    self.wait_for_forwarded(valid_stamp_keys, start.stamp)
    time.sleep(DELIVERY)
    self.advance_clock()
    return start

def outputs_since(self, start: StepStart) -> List[Odometry]:
    """Return the EKF's outputs after the step's start, stamped at its time or later."""
    return [message for message in self.ekf_outputs.since(start.output_count_before)
            if message.header.stamp >= start.stamp]

def step(self, wheel_rate: float, imu_inputs: Sequence[ImuInput] = ()) -> Odometry:
    """Run one step and return the EKF's last output for it, which has to come.

    One step:
    1. Publish the step's wheel odometry, stamped with the step's ROS time, and its IMU
       samples, each stamped with that time plus the sample's offset (publish_inputs()).
    2. Wait on the wall clock until the IMU sample validator's output for the step's valid
       samples reaches the test (wait_for_forwarded()). The EKF subscribes to the same
       topic.
    3. Wait DELIVERY more, for the inputs to arrive at the EKF.
    4. Advance the clock by STEP (advance_clock()). The EKF's 50 Hz update then processes the
       inputs.
    5. Wait, with the time limit WAIT, for an EKF output stamped at the step's time or later.
    advance() does 1 to 4.
    """
    start = self.advance(wheel_rate, imu_inputs)
    wait_for(lambda: bool(self.outputs_since(start)),
             'no EKF output for the step at {:.2f} s'.format(start.stamp.to_sec()))
    return self.outputs_since(start)[-1]

    The five things of one step, as the docstring of step() numbers them:

    1. Publish the inputs: publish_inputs() publishes the step's wheel odometry, stamped with the step's ROS time, and its IMU samples, each stamped with that time plus the sample's offset.
    2. Wait for the validator: wait_for_forwarded() waits on the wall clock until the validator's output for the step's valid samples reached the test. The EKF subscribes to the same topic.
    3. Wait DELIVERY: advance() sleeps DELIVERY, 20 ms of wall time, so that the inputs reach the EKF before the clock moves.
    4. Advance the clock: advance_clock() adds STEP to self.now and publishes the new clock. The EKF's update runs 50 times per second of ROS time, so the new clock lets the filter process the step's inputs.
    5. Wait for the EKF: step() waits until the filter published an output that is stamped at the step's time or later, at most WAIT, 5 s of wall time. step() returns the last such output.

    def publish_inputs(self, stamp: rospy.Time, wheel_rate: float,

def expect(self, imu_input: ImuInput) -> None:
    """Count the sample as one that the validator has to forward or to drop."""
    if imu_input.drop_reason is None:
        self.expected_forward_count += 1
    else:
        self.expected_drops[imu_input.drop_reason] += 1

def wait_for_forwarded(self, stamp_keys: Sequence[StampKey], stamp: rospy.Time) -> None:
    """Wait on the wall clock until the validator forwarded the samples with these stamps."""
    wait_for(lambda: self.forwarded_stamp_keys.contains_all(stamp_keys),
             "the validator didn't forward the IMU samples of the step at {:.2f} s".format(
                 stamp.to_sec()))

def advance_clock(self) -> None:
    """Move the ROS time on by STEP and publish it."""
    self.now += STEP
    self.clock_publisher.publish(Clock(self.now))
    • publish_inputs(): publishes the wheel odometry, stamped with the step's time stamp. For each ImuInput of the step, it publishes an IMU sample stamped stamp plus the sample's offset, and passes the ImuInput to expect(). It returns valid_stamp_keys, the stamps of the samples that the validator has to forward.
    • expect(): counts what the validator has to do with the sample. A sample without a drop_reason adds one to self.expected_forward_count. A sample with a drop_reason adds one to that reason in self.expected_drops.
    • wait_for_forwarded(): waits with wait_for() until self.forwarded_stamp_keys contains every stamp of stamp_keys. on_validated() appends to this log the stamp of each sample that arrives on the topic /diffbot/imu/data_validated.
    • advance_clock(): adds STEP to self.now and publishes the new time on the topic /clock.

    Every wait is bounded: it ends when its message arrived, or it fails the test after WAIT. The waits reduce how much the result depends on the computer's speed. They don't prove that the EKF received each input before the clock moved. The checks of the estimate don't depend on that: the filter fuses an input that arrives late one step later, and these checks look at the last output of a phase and at the highest of the outputs that the test keeps in a phase.

    def assert_yaw_rate(self, output: Odometry, expected: float, delta: float, what: str) -> None:

def validator_values(self, array_count_before: int) -> Optional[Dict[str, str]]:
    """Return the validator's latest status values after the first array_count_before arrays.

    None if no array after them has a status of the validator.
    """
    for array in reversed(self.diagnostics.since(array_count_before)):
        for status in array.status:
            if VALIDATOR_STATUS_NAME in status.name:
                return {pair.key: pair.value for pair in status.values}
    return None

def wait_for_validator_diagnostics(self) -> Dict[str, str]:
    """Advance the clock without IMU samples and return the validator's latest values.

    The validator publishes its diagnostics once per second of ROS time.
    """
    array_count_before = self.diagnostics.count()
    start = self.now
    while self.now < start + DIAGNOSTICS_WAIT:
        self.step(WHEEL_RATE)
    wait_for(lambda: self.validator_values(array_count_before) is not None,
             'phase 7: no status of the IMU sample validator on the topic /diagnostics')
    values = self.validator_values(array_count_before)
    assert values is not None  # wait_for() returned
    return values

def assert_diagnostic_counts(self, values: Dict[str, str]) -> None:
    """Assert that values has the expected count for forwarded and for each drop reason."""
    self.assertEqual(str(self.expected_forward_count), values.get(FORWARDED_KEY),
                     'phase 7: forwarded samples')
    for reason, count in self.expected_drops.items():
        self.assertEqual(str(count), values.get(DROPPED_KEY_PREFIX + reason),
                         'phase 7: dropped, ' + reason)
    self.assertEqual(len(self.expected_drops) + 1, len(values),
                     'phase 7: other drop reasons: {}'.format(values))
    • wait_for_validator_diagnostics(): notes in array_count_before how many messages of the topic /diagnostics the test has so far. Then it runs steps without IMU samples until the clock is DIAGNOSTICS_WAIT, 1.5 s, further. That is longer than the 1 s between two reports, so a report from after the last IMU sample arrives. The method returns the keys and values of the validator's latest status.
    • validator_values(): looks through the messages that arrived after the first array_count_before, the newest first, and finds the validator's status by its name. The name contains VALIDATOR_STATUS_NAME, "IMU sample validator". The test writes this text and the keys out and doesn't import them from the script, so the test pins what a user reads on the topic.
    • assert_diagnostic_counts(): the value of FORWARDED_KEY, "Samples forwarded", has to be self.expected_forward_count. For each reason, the value of "Dropped, " plus the reason has to be the test's count. The last assertion compares the number of values with the number of expected reasons plus one, so the status has no other reason to drop a sample.

    What the test doesn't show

    • The robot's wheel odometry: on the robot, the wheel odometry arrives at most 10 times per second. In this test, both inputs arrive in every step, 50 times per second of ROS time.
    • Real sensors: the inputs have no noise, no bias and no delay. How the real gyroscope behaves is a measurement on the robot, as Limits says.
    • The pose and the transform: the test checks the forward speed \(v_x\) and the yaw rate \(\omega_z\) of the filter's output, and its two frames. It doesn't check the position, the heading \(\theta\) or the transform odom → base_footprint on the topic /tf. The test in Gazebo compares the heading with the simulated robot's true turn.
    • Remo's URDF model: the test loads DiffBot's URDF model, whose imu_link has the axes of base_footprint. The test in Gazebo runs with both robots' URDF models.
    • The validator's limits themselves: the samples to drop lie far outside the limits, 0.5 s against 0.1 s and 0.02 s. The validator's unit tests probe the limits to the microsecond.
