    Geometry Test

    Each robot's wheel radius and wheel separation are written down twice: in its URDF, the robot's model, and in the controller's geometry.yaml. test_geometry_consistency.py checks that the two agree, for DiffBot and Remo, without starting Gazebo or the robot. It also checks the wheel joints that the controller drives by name. CI runs it on every pull request, with the other tests.

    The simulation test drives the robots in Gazebo and would notice large differences only: a wheel separation that's off by less than about 7 % can pass its turn. Neither test can show that the URDF matches the real wheels. That needs a measurement on the robot (diffbot#138 for Remo, diffbot#161 for DiffBot).

    What it compares

    For Remo, these are the values. The two values in each row must be the same:

    Remo's URDFRemo's geometry.yaml
    front_left_wheel
    radius 0.033 m    		⟷wheel_radius
    0.033
    front_right_wheel
    radius 0.033 m    		⟷wheel_radius
    0.033
    Wheel joints
    0.144 m apart    		⟷wheel_separation
    0.144
    • The radii are the wheels' collision shapes: the simple spheres that Gazebo uses for contacts, not the meshes you see.
    • The separation is the straight-line distance between the two wheel joints, the points the wheels turn about. front_left_wheel_joint is at y = 0.072 m and front_right_wheel_joint at y = −0.072 m, with the same x and z.
    • The tolerance is 0.1 mm: a larger difference fails.

    xacro computes the URDF's values from the YAML files of the robot's description package, for Remo front_wheel.yaml and base.yaml in remo_description, for DiffBot the same files in diffbot_description/config/diffbot. The test compares these nominal values only. A calibration of the real robot belongs in diff_drive_controller's multipliers, such as wheel_separation_multiplier, "used to account for a difference between the robot model and a real robot". The test leaves them alone.

    class TestModels(unittest.TestCase):
    """Each robot's URDF and controller configuration agree, as the launch files load them."""

    def check(self, model: str, params: Params) -> None:
        """Assert that the URDF in params agrees with the controller's parameters."""
        self.assertEqual(mismatches(params), [],
                         '{}: URDF and controller disagree'.format(model))

    def test_simulation(self) -> None:
        for model in MODELS:
            with self.subTest(model=model):
                params = dump_params('diffbot_gazebo', 'diffbot_view.launch', model=model)
                params.update(dump_params('diffbot_control', 'diffbot_control.launch',
                                          model=model, rqt_robot_steering='false'))
                self.check(model, params)

    def test_robot(self) -> None:
        for model in MODELS:
            with self.subTest(model=model):
                self.check(model, dump_params('diffbot_base', 'diffbot.launch', model=model))

    It checks each robot in MODELS, DiffBot and Remo. test_simulation() combines the parameters of the two launch files that start the simulation: diffbot_view.launch loads the URDF, and diffbot_control.launch loads the controller's configuration. test_robot() takes the parameters of diffbot.launch, which loads both on the real robot. check() fails when mismatches() reports a problem.

    def dump_params(package: str, launch_file: str, **launch_args: str) -> Params:
    """Return the parameters that a launch file sets, by parameter name.

    roslaunch --dump-params reads the launch file and the files it includes, and prints the
    parameters as YAML, without starting a node.
    """
    command = ['roslaunch', '--dump-params', package, launch_file]
    command += ['{}:={}'.format(name, value) for name, value in launch_args.items()]
    launch = ' '.join(command[2:])
    try:
        result = subprocess.run(command, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
                                universal_newlines=True, check=True)
    except subprocess.CalledProcessError as error:
        raise RuntimeError(
            'roslaunch failed for {}: {}'.format(launch, error.stderr.strip())) from error
    params = yaml.safe_load(result.stdout)
    # roslaunch ends with 0 and prints nothing when it can't load a file, for example when a
    # package such as remo_description is missing
    if not isinstance(params, dict):
        raise RuntimeError(
            'roslaunch printed no parameters for {}: {}'.format(launch, result.stderr.strip()))
    return params

    roslaunch --dump-params reads a launch file and the files it includes, and prints the parameters that it would set, as YAML. It starts no node, so these are the values the launch files would load, not values read from a running robot. When roslaunch can't load a file, for example because remo_description is missing, it prints nothing and still ends without an error. So an empty result is an error too.

    What params holds: every parameter that the launch files set, by its full name. Two kinds matter for the test:

    • The controller's configuration, from diffbot_control.yaml and the robot's geometry.yaml: for example /diffbot/mobile_base_controller/wheel_radius, a number.
    • /diffbot/robot_description, the URDF that xacro expanded from the description package, all of it as one string.

    mismatches() takes the whole dictionary, and wheel_setup() (step 2) reads the URDF from it. Both come from the real launch files, which is why they're what the robot gets. The simulation's dictionary combines two launch files, so one dictionary alone doesn't prove that two values come from the same file.

    class WheelSetup(NamedTuple):
    """The drive wheels as the URDF and the controller's parameters describe them."""

    robot: ET.Element
    joints_by_name: Dict[str, ET.Element]
    left_joint_names: List[str]
    right_joint_names: List[str]
    wheel_radius: float
    wheel_separation: float
    # A list of joint names when the parameter is set right, but it can be anything or missing
    hardware_joint_names: object

    @property
    def wheel_joint_names(self) -> List[str]:
        """Return the controller's wheel joints, the left ones first."""
        return self.left_joint_names + self.right_joint_names

    def urdf_wheel_joints(self) -> List[ET.Element]:
        """Return the controller's wheel joints that are in the URDF."""
        return [self.joints_by_name[name] for name in self.wheel_joint_names
                if name in self.joints_by_name]


def wheel_joint_names(params: Params, side: str) -> List[str]:
    """Return the controller's wheel joints on one side, 'left' or 'right'.

    diff_drive_controller takes a joint name or a list of joint names for each side.
    """
    names = params[CONTROLLER + side + '_wheel']
    return [names] if isinstance(names, str) else list(names)


def wheel_setup(params: Params) -> WheelSetup:
    """Return the drive wheels as the launch files' parameters describe them.

    params holds the URDF under ROBOT_DESCRIPTION, next to the parameters of the controller and
    of the hardware interface, as roslaunch --dump-params prints them.
    """
    robot = ET.fromstring(params[ROBOT_DESCRIPTION])
    return WheelSetup(
        robot=robot,
        joints_by_name={joint.get('name', ''): joint for joint in robot.findall('joint')},
        left_joint_names=wheel_joint_names(params, 'left'),
        right_joint_names=wheel_joint_names(params, 'right'),
        wheel_radius=params[CONTROLLER + 'wheel_radius'],
        wheel_separation=params[CONTROLLER + 'wheel_separation'],
        hardware_joint_names=params.get(HARDWARE_JOINTS),
    )

    def transmission_interfaces(robot: ET.Element) -> Tuple[Dict[str, str], Set[str]]:
    """Return each joint's first transmission interface, and the joints in shared transmissions.

    Gazebo's DefaultRobotHWSim gives a joint the first interface of its transmission, and skips a
    transmission with more than one joint, so only single-joint transmissions give an interface.
